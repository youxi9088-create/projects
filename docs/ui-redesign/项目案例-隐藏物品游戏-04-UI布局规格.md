## 4. 游戏页（`.game-shell`）—— **核心修正区**

### 4.1 问题诊断

现有 `grid-template-rows: auto auto auto minmax(0, 1fr) auto`，前三项实测高度：

| 项 | 高度 | 构成 |
|---|---|---|
| `.app-nav` | 58px | `min-height: 58px` |
| `.topbar` | ≈ 86px | eyebrow 15px + `margin-bottom: 3px` + `h1` 38px×1.05 = 40px + `.story-beat` 20px（13px×1.55）+ `margin-top: 8px` |
| `.case-breadcrumb` | 34px | `min-height: 34px` |
| `gap × 4` | 36px | `gap: 9px`，5 行之间 4 条间隙 |
| `padding-block × 2` | 24px | `padding-block: 12px` |
| **顶部固定开销合计** | **≈ 238px** | — |

在 800px 高的视口上，画布只剩 `800 − 238 − 56(mission) − 14(margin) = 492px`（**61.5%**）；在 720px 高的笔记本上只剩 **412px（57.2%）**，宽度被 3:2 约束为 **738px**——寻物画面被严重挤压，正是"UI 丑"的体感来源之一。

另：`.mission-panel` 与 `.play-area` 之间还有 `margin: 14px auto 0`。

### 4.2 修正方案：**三层头部合并为一层**

保留 DOM 不变，用 CSS 把 nav / topbar / breadcrumb 压进**同一条 56px 高的头部带**：

```css
.game-shell {
  --game-chrome: 168px;   /* 头部 56 + mission 64 + gap 8×2 + padding-block 32 */
  height: 100svh; min-height: 0;
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;   /* 旧：auto auto auto minmax(0,1fr) auto */
  gap: var(--space-2);                            /* 8px，旧 9px */
  overflow: hidden;
  padding: var(--space-4) var(--space-4) var(--space-4);  /* 16px，旧 padding-block 12px */
}

/* 头部带：把 nav 与 topbar 合并成同一行 flex */
.game-shell .app-nav {
  grid-row: 1;
  min-height: 56px;
  grid-template-columns: auto 1fr auto;   /* 品牌 | 案件信息 | 进度+声音 */
  gap: var(--space-4);
}
.game-shell .topbar {
  grid-row: 1;                             /* 与 nav 同行 */
  display: contents;                       /* 让 topbar 的子元素直接参与 nav 的三栏栅格 */
}
```

> **关键点**：`.topbar { display: contents }` 让其两个子 `<div>`（案件信息、进度）与 `.audio-controls` 直接成为 `.app-nav` 栅格的项，在**不改动 React 结构**的前提下把两行压成一行。DOM 顺序保持 `nav → topbar`，栅格列依次为：`app-brand`（nav 内）→ `nav-links` → `my-cases` → `topbar 案件信息` → `progress` → `audio`。

因此 `.app-nav` 在游戏页下改为 6 列：

```css
.game-shell .app-nav {
  grid-template-columns: auto auto 1fr auto auto auto;
  /* brand | nav-links | 案件信息(撑开) | progress | audio | casebook */
  gap: var(--space-3);
}
```

### 4.4 画布区（`.play-area`）

```css
.play-area {
  grid-row: 2;
  position: relative;
  justify-self: center;
  /* 高度驱动：由 grid 行高与视口上限共同决定，宽度由 aspect-ratio 反推，
     避免旧写法中 width:100% 与 aspect-ratio 争夺、导致比例失效 */
  height: 100%;
  max-height: calc(100svh - var(--game-chrome));
  width: auto;
  max-width: 100%;
  aspect-ratio: 3 / 2;
  border: 1px solid var(--border-default);   /* 旧 rgba(237,188,93,.45) */
  border-radius: var(--radius-md);           /* 10px，旧 18px */
  overflow: hidden;
  background: var(--surface-base);
  /* box-shadow: 0 20px 60px #000a  —— 删除 */
}
.game-shell .game-canvas { width: 100%; height: 100%; min-height: 0; aspect-ratio: auto; }
```

**画布面积校验**（`--game-chrome = 168px`；内容区最大宽 1200px，宽屏下画布受 1200 宽上限约束）：

| 视口高 | 行高 `100svh−168` | 由比例反推宽 | 实际画布（受 `max-width:100%` 收敛后） | 占视口高比 | 旧方案占比 |
|---|---|---|---|---|---|
| 1080px | 912px | 1368px → 超 1200 | **1200 × 800**（宽度封顶，高度由比例回算） | **74.1%** | 58% |
| 900px | 732px | 1098px | **1098 × 732** | **81.3%** | 62% |
| 800px | 632px | 948px | **948 × 632** | **79.0%** | 61.5% |
| 720px | 552px | 828px | **828 × 552** | **76.7%** | 57.2% |
| 640px | 472px | 708px | **708 × 472** | **73.8%** | 52% |

> 全部 ≥ 73%，满足 `项目案例-隐藏物品游戏-03-UI视觉方向.md` P4（画布 ≥ 62vh）且显著优于旧版。
> **注意**：`width: auto` 必须显式声明，否则 `.play-area` 会继承块级元素的 `width: auto`（此处正确）但与 `height: 100%` 组合时，旧代码的 `width: min(1280px, 100%)` 会让 `aspect-ratio` 失效——这正是当前版本在不同视口下画布比例不稳定的原因。

### 4.6 **提示浮层（`.hint-toast`）—— 缺陷 #1 修正**

**问题**：`position: fixed; bottom: 104px; left: 50%` 的浮层固定悬在画面底部 104px 处。寻物游戏的物品恰恰最容易藏在画面下半部（桌面下沿、地板、画框底部），提示一出现就把目标区域整体盖住，玩家读完提示后目标已被遮住，无法立即定位。

**修正方案 A（推荐）：改为网格流内元素，提示出现时画布让位而非被遮挡**

```css
.game-shell { grid-template-rows: auto minmax(0, 1fr) auto auto; }  /* 增加第 4 行 */
.hint-toast {
  grid-row: 4;
  position: static;                        /* 取消 fixed */
  justify-self: center;
  max-width: min(560px, 100%);
  margin: 0 auto;
  padding: var(--space-3) var(--space-4);
  border: 1px solid var(--border-default);
  border-left: 3px solid var(--accent-primary);   /* 牛皮纸便签的强调边 */
  border-radius: var(--radius-sm);
  background: var(--paper);                /* 牛皮纸便签 */
  color: var(--text-on-paper);
  font-family: var(--font-sans); font-size: 15px; line-height: 1.6;
  text-align: center;
  box-shadow: var(--shadow-3);             /* 浮层唯一允许用 shadow-3 的位置 */
}
```

网格第 4 行为 `auto`，无提示时高度为 0（元素不渲染即可），有提示时画布 `minmax(0,1fr)` 自动收缩——**目标物品永远可见**。

**修正方案 B（备选，若产品坚持浮层形式）：锚定到画面顶部**

寻物场景中画面顶部（天花板、壁画上部、书架顶层）的藏物密度显著低于底部，把浮层移到顶部可把遮挡损失降到最低：

```css
.hint-toast {
  position: absolute;                      /* 相对 .play-area 定位 */
  grid-row: 2; align-self: start; justify-self: center;
  top: var(--space-3); z-index: var(--z-toast);
  max-width: min(560px, calc(100% - var(--space-6)));
  /* 其余同方案 A */
}
```

**无障碍补充**（两种方案都需要）：

```tsx
<div className="hint-toast" role="status" aria-live="polite">{hintText}</div>
```

`role="status"` 已存在，需补 `aria-live="polite"`，确保屏幕阅读器播报而不打断。

## 8. 版式改动汇总对照

| 界面 | 主要问题 | 修正要点 |
|---|---|---|
| 首页 Hero | 三段渐变 + 70px 投影 + 洗光层三重叠加 | 保留单段遮罩，删除投影与 `::after`；右侧改拍立得 + 胶带 |
| 案件卡片 | 径向渐变 + 36px 投影 + 84% 端遮罩 | 纯色卡 + 1px 边 + 图钉；hover 只提亮底色与边框 |
| 顶部导航 | 58px 高、按钮 40px、半透明底 | 56px 高、按钮 44px、不透明 `--surface-panel`、无投影 |
| **游戏页** | **顶部三层占 246px + 画布被挤压** | **三层合并为一层 56px；`--game-chrome: 168px`；画布占比 ≥ 70%** |
| **提示浮层** | **`bottom: 104px` 遮挡藏物区** | **改为网格第 4 行流内元素（方案 A）或锚定画面顶部（方案 B）** |
| 线索栏 | 14px 外边距、54px 卡高、渐变底 | 0 外边距、56px 卡高、`--surface-sunken` 纯色 |
| 委托流程 | 光环 box-shadow、半透明容器底 | 光环改实描边；容器改不透明 |
| 章节过场 | `text-shadow` 使衬线中文发糊 | 删除 `text-shadow`，由 `::after` 渐变承担对比 |
| 结算弹窗 | 径向渐变 + 80px 投影 | 牛皮纸 `--paper` + 图钉 + `--shadow-3` |
