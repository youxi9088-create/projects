# 星图档案 · 视觉方向文档（Evidence Board）

> 适用范围：首页选关、主线游戏 HUD、自定义委托流程（CreatorFlow）、章节过场、结算弹窗
> 目标：把当前「深棕 + 大投影 + radial-gradient 堆叠」的旧观感，改造为**干净的证物板**质感——暖调保留，但提亮、去油、去堆叠。
> 本文只定义**方向与使用规范**，具体数值见 `项目案例-隐藏物品游戏-06-UI设计令牌.md`，旧值替换见 `项目案例-隐藏物品游戏-07-UI颜色迁移映射.md`。

## 一、设计原则（5 条）

| # | 原则 | 含义 | 判定标准（可被验收） |
|---|---|---|---|
| P1 | **一个表面只做一件事** | 每个容器只允许使用「底色 / 描边 / 装饰」三选二，禁止 `border + gradient + box-shadow + ::after 遮罩` 四件套同时出现 | 任一选择器内 `background-image` 与 `box-shadow` 不得同时非零；有 `::after` 遮罩的容器不得再带 `box-shadow` |
| P2 | **装饰是语义，不是涂料** | 图钉 / 胶带 / 拍立得 / 牛皮纸标签只在能传达「这是一份被钉在板上的材料」时出现；纯列表、纯按钮不贴装饰 | 装饰元素数量：单屏首页 ≤ 6 个图钉、≤ 2 条胶带；游戏 HUD 内 **0** 个装饰 |
| P3 | **层级靠留白与分隔线，不靠投影** | 卡片与背景的区分由 1px 描边 + 明度差承担；投影只用于「脱离页面」的浮层（弹窗 / 浮层提示） | 静态卡片只用 `--shadow-1`；`--shadow-3` 仅允许用于 `.completion-card`、`.hint-toast`、`.outro-*` |
| P4 | **画布是主角，HUD 是便签** | 寻物画面占据尽可能大的面积，所有 HUD 元素退化为低刺激的小尺寸纸片 | 游戏页画布可视高度 ≥ 视口 62%；HUD 区域不得使用任何 `radial-gradient` |
| P5 | **色值必须来自 Token** | 提交代码中不允许出现裸 hex（含 8 位 alpha） | CI/Codereview 检查：`App.css` 与 `index.css` 中裸 hex 出现次数 = 0 |

## 二、视觉身份

### 2.1 一句话定义

> **一张被台灯照亮的软木证物板**：牛皮纸档案袋、图钉钉住的照片与便签、细网格纸写着的调查笔记。

### 2.2 三个关键词与反面清单

| 关键词 | 正面表现 | 明确禁止 |
|---|---|---|
| **干净** | 大面积低反差底色 + 明确的 1px 分隔线 + 大量留白 | `radial-gradient` 光晕、多层叠加遮罩、60px 模糊大投影 |
| **轻** | 元素只靠「薄纸 + 细边」立起来，看着能被取下 | `inset 0 1px rgba(255,...)` 高光内阴影、3 层以上 box-shadow |
| **暖而不油** | 暖棕底 + 降低饱和的琥珀金（去红、去橙） | 高饱和橙金 `#d69537`、橙→棕渐变按钮、大面积色相偏移 |

### 2.3 与旧版的关键差异

| 维度 | 旧版 | 新版 |
|---|---|---|
| 底色明度 | L ≈ 6%（`#120d0a`），极暗且发闷 | L ≈ 6% → 但面板提到 L ≈ 15%，层次拉开 |
| 金色 | 22 种高饱和橙金，明度差 < 3% | 1 种 `#e5b76b`，饱和度从 72% 降到 62%，去油 |
| 卡片 | 四件套堆叠（边 + 径向渐变 + 投影 + ::after 渐变遮罩） | 底色 + 1px 描边 + 可选 1 枚图钉，投影仅 `--shadow-1` |
| 分隔 | 靠投影与明度微差（不可辨） | 靠 1px `--border-default` 描边 + 4pt 网格留白 |
| 画布 | 被 `border + radius 18 + shadow 0 20px 60px` 三层包住 | 仅 1px 描边 + `--radius-md`，无投影 |

## 三、装饰母题使用规范

四个母题的**适用位置 / 禁用场景 / 实现约束**如下。所有装饰统一由 `::before` / `::after` 或独立的 `<span aria-hidden="true">` 承担，**必须 `pointer-events: none`**，且**不得承载任何文字内容**（无障碍与可选中性）。

### 3.1 图钉（Pushpin）

| 项 | 规范 |
|---|---|
| **形态** | 8×8px 圆形，上半为金属高光 `#e5b76b`，下半 6×5px 针影 `rgba(23,13,6,.45)`；或纯色圆 + 1px 深色描边 |
| **适用位置** | ① 案件卡片（`.level-card`）左上角；② 主题卡（`.theme-card`）被选中时顶部中央；③ 章节地图节点（`.map-node.is-open`）；④ 结算弹窗卡片顶部中央 |
| **禁用场景** | 游戏 HUD 内所有元素（导航、提示按钮、线索卡、进度）；输入框、下拉框、复选框；`.target-card`（尺寸过小，图钉会糊成一团）；任何可点击区域的正中心 |
| **数量约束** | 单屏 ≤ 6 枚；同一卡片 ≤ 1 枚 |
| **状态联动** | 默认用 `--text-tertiary`（灰金属）；hover / 选中用 `--accent-primary`（黄铜）；**不使用红色图钉表示错误状态**（红色图钉只用于「未读便签」这一装饰语义，与语义错误色区分开） |

### 3.2 胶带（Tape）

| 项 | 规范 |
|---|---|
| **形态** | 半透明米白长条，`width: 64px; height: 20px; background: rgba(233,220,190,.55)`，`transform: rotate(-2deg)`，两端 1px 毛边用 `clip-path: polygon()` 实现 |
| **适用位置** | ① 首页 Hero 内的「当前案件预览」拍立得顶部；② 自定义委托流程中「模型解读」信息卡（`.design-handoff-summary`）左上；③ 章节过场引用块（`.story-copy blockquote`）左上 |
| **禁用场景** | 任何 `<button>` 上（会干扰可点击区域的可辨识度）；输入框；移动端 ≤ 600px（旋转长条在小屏易与内容重叠，直接隐藏） |
| **数量约束** | 单页 ≤ 2 条；不与图钉出现在同一元素上 |

### 3.3 拍立得（Polaroid）

| 项 | 规范 |
|---|---|
| **形态** | 白/牛皮纸外框（`--paper`），内嵌 4:3 图片，图片与外框间距 8px，下方留 16px 手写风格标题区（用 `--font-serif`，≥ 15px）；外框 `border-radius: var(--radius-sm)`，仅用 `--shadow-1` |
| **适用位置** | ① 首页 Hero 右侧「正在调查」预览卡（`.home-case-preview`）；② 物品图鉴卡片（`.object-gallery-card`）；③ 故事书架封面（`.shelf-book`） |
| **禁用场景** | 案件卡片（`.level-card`）本身——它是「牛皮纸档案袋」，不是照片，两者母题不得混用；游戏 HUD；任何纯文字容器 |
| **数量约束** | 首页 ≤ 2 张；图鉴页可平铺（此时取消旋转，避免栅格错乱） |

### 3.4 牛皮纸标签 / 档案袋（Kraft Tag）

| 项 | 规范 |
|---|---|
| **形态** | 圆角矩形纸片，`background: var(--paper)`，`color: var(--text-on-paper)`，左上角可有一枚图钉；标题用 `--font-serif` ≥ 17px，正文用 `--font-sans` 15px |
| **适用位置** | ① 案件卡片（`.level-card`）整体；② 案件档案弹窗（`.case-intro-card`）内容区；③ 调查笔记条目（`.notes-list article`）；④ 大纲章节条目（`.chapter-outline article`）；⑤ 便签式提示浮层（`.hint-toast`） |
| **禁用场景** | 底色为深棕的 HUD 条（nav / topbar / mission-panel）——它们属于「板子」而非「纸片」；按钮（按钮用描边 + 暖底，不用纸白，否则与纸片层级冲突）；`pre` 代码块（用 `--surface-sunken` + 等宽字体） |
| **数量约束** | 无上限，但同屏纸片之间须保持 ≥ `--space-4`(16px) 间隙 |

### 3.5 母题冲突裁决规则

当两个母题都能用在同一位置时，按以下优先级取一：

```
牛皮纸档案袋（承载文字内容）
  > 拍立得（承载图片内容）
  > 图钉（用于"钉住"以上两者）
  > 胶带（用于"贴住"拍立得，仅静态展示位）
```

**硬性禁止**：同一元素上同时出现图钉 + 胶带；同一屏内图钉与胶带总数 > 8。

## 四、字体方案

### 4.1 问题诊断

现状 `font-family: Georgia, 'Noto Serif SC', serif` 全局生效，导致：

1. **12px eyebrow**（`.eyebrow`、`.level-number`、`.creator-flow-progress`）用中文衬线 + `font-weight: 700` + `letter-spacing: .16em`，Windows 下宋体/思源宋体小字笔画粘连、加粗后墨团化 → 显脏。
2. **Georgia 无中文字形**，会 fallback 到 Noto Serif SC；未安装时再 fallback 到 SimSun，**SimSun 在 12–14px 是点阵字**，观感最差。
3. HUD 数字（`{n} / {m}`、计时器 `00:00`）用衬线导致数字宽度不齐、跳动。

### 4.2 双轨字族（核心方案）

**中文衬线只用于「叙事 / 展示」，其余一切 UI 文本改用无衬线。**

```css
/* 展示 / 叙事轨：章节标题、案件名、过场文案、案件档案正文、blockquote */
--font-serif: Georgia, "Songti SC", "Source Han Serif SC", "Noto Serif SC", "SimSun", serif;

/* 界面 / 功能轨：导航、eyebrow、按钮、HUD、表单、提示、代码块 */
--font-sans: "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei UI",
             "Source Han Sans SC", "Noto Sans SC", system-ui, -apple-system, sans-serif;

/* 代码 / 模型产物：.generated-files pre */
--font-mono: "Cascadia Mono", "Sarasa Mono SC", "Consolas", "Courier New", monospace;
```

排序说明：
- `--font-serif` 拉丁字符**优先 Georgia**（保留原有西文调性），中文由 `Songti SC`（macOS）→ `Source Han Serif SC` / `Noto Serif SC` → `SimSun`（Windows 兜底）承接。
- `--font-sans` 优先 `PingFang SC` / `HarmonyOS Sans SC`（国产系统高分屏表现最好），Windows 落到 `Microsoft YaHei UI`（**注意带 `UI` 后缀**，其字距与 hinting 优于 `Microsoft YaHei`）。
- `system-ui` 放倒数第二位，避免部分 Linux 环境吃掉整条链。

### 4.3 字号下限（硬性）

| 文本类型 | 字族 | 字号下限 | 字重上限 | 其它 |
|---|---|---|---|---|
| 章节/页面大标题 `h1` | serif | **32px**（桌面）／ 26px（≤600px） | 700 | `letter-spacing: .02em` |
| 卡片标题、弹窗标题 `h2` | serif | **22px** | 700 | — |
| 案件名、书籍名 `<strong>` | serif | **17px** | 700 | 17px 是中文衬线可读的临界值，低于此值必须切 sans |
| 正文段落 `p` | sans | **15px** | 400 | `line-height: 1.7` |
| 卡片描述 `<small>` | sans | **13px** | 400 | `line-height: 1.65` |
| **eyebrow / 标签 / 序号** | **sans** | **12px** | **600**（禁止 700） | `letter-spacing: .12em`；全大写仅对拉丁文生效，中文不加 `text-transform` |
| HUD 数字、计时器、进度 | sans | **13px**（数字 ≥ 20px） | 700 | 必须 `font-variant-numeric: tabular-nums` |
| 按钮文案 | sans | **14px** | 600 | — |
| 代码块 `pre` | mono | **12px** | 400 | `line-height: 1.6` |

> **关键规则：任何 ≤ 14px 的文本一律强制走 `--font-sans`。** 衬线中文在 15px 以下不可读，这是本次改版最重要的一条字体约束。

### 4.4 Windows 小字抗脏处理（必做）

```css
:root {
  font-synthesis: none;                 /* 已有：禁止伪粗体/伪斜体合成 */
  -webkit-font-smoothing: antialiased;  /* 关掉 Windows 次像素渲染导致的彩边 */
  -moz-osx-font-smoothing: grayscale;
  text-rendering: optimizeLegibility;
}

/* 衬线中文：禁止 < 17px 与 700 字重同时出现 */
.eyebrow, .level-number, .level-start,
.case-difficulty span, .case-objective span {
  font-family: var(--font-sans);
  font-weight: 600;
  font-size: 12px;
  letter-spacing: .12em;
}
```

补充要求：
1. **`.eyebrow` 的 `letter-spacing` 从 `.16em` 降到 `.12em`** —— 0.16em 在 12px 中文下会拉出 1.92px 字距，配合衬线笔画直接糊成灰条。
2. **禁用 `font-weight: 700` 的衬线小字** —— 中文粗衬线在 Windows GDI 渲染下会并笔。
3. **`text-shadow` 一律移除**（`.outro-copy` 当前有 `text-shadow: 0 3px 14px #000`，改为在其下垫一层 `--surface-scrim` 渐变，避免文字边缘发糊）。
4. 数字统一 `font-variant-numeric: tabular-nums`，防止计时器抖动。

### 4.5 字号—字族速查

```
≥ 22px  + 叙事语义   → serif  (h1 / h2 / blockquote / 过场文案 / 案件档案)
17–21px + 名称语义   → serif  (章节名 / 书名 / 案件名)
≥ 17px  + 正文语义   → sans   (段落 / 描述)
≤ 14px  任意         → sans 强制 (eyebrow / 标签 / 按钮 / HUD 小字)
任意    + 数字       → sans + tabular-nums
任意    + 代码       → mono
```

## 六、验收清单

- [ ] `App.css` / `index.css` 中裸 hex 数量为 0，全部走 `var(--*)`
- [ ] 全站 `radial-gradient` 出现次数 = 0
- [ ] `box-shadow` 值种类 = 3（`--shadow-1/2/3`），无裸写
- [ ] `!important` 数量为 0（`.primary-action` 的 4 个必须移除，改用选择器权重或 CSS 层级顺序）
- [ ] 所有 ≤ 14px 文本 `font-family` 为 `--font-sans`
- [ ] 游戏页画布可视高度 ≥ 62vh
- [ ] `.hint-toast` 不再使用 `bottom: 104px` 固定定位覆盖画面
- [ ] 所有装饰元素 `pointer-events: none` 且不承载文字
