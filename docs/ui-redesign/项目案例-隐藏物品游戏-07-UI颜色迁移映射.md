# 星图档案 · 旧 hex → 新 Token 映射表

> **用途**：工程侧批量替换的直接依据。三列结构：**旧值 → 新 Token → 理由**。
> **统计口径**：对 `apps/web/src/App.css`（282 行）与 `index.css`（21 行）全量扫描，共提取 **216 个唯一色值**（6 位 hex 179 个、3 位 hex 7 个、8 位 alpha hex 30 个）。以下表 A–J 覆盖**全部**色值，其中需求方点名的 29 个深棕、22 个金色逐条单列。
> **执行顺序建议**：先按 §0 的「全局替换脚本顺序」跑，再按 §11 手工处理渐变与 `!important`。

---

## 0. 批量替换执行顺序（重要）

色值合并会造成**多对一**映射，因此必须**先替换容易冲突的方向**。按以下批次顺序执行，每批之间跑一次构建：

| 批次 | 内容 | 说明 |
|---|---|---|
| **B0** | 删除所有 `radial-gradient` 与多段 `linear-gradient` | 先把渐变整段替换为纯色/单段遮罩，避免渐变内的 hex 与卡片 hex 混淆 |
| **B1** | 替换「文字色」（表 C） | 文字色数量最多、彼此最相近，先归一 |
| **B2** | 替换「绿色系」（表 E）与「青绿系」（表 F） | 色相独立，不会与棕色混淆 |
| **B3** | 替换「红色系」（表 G） | 同上 |
| **B4** | 替换「金色系」（表 B） | 金色与浅棕文字色接近，必须在 C 之后做 |
| **B5** | 替换「深棕底」（表 A） | 数量最多，放最后用全局替换 |
| **B6** | 替换「中棕描边」（表 D） | 与 A 的深色端部有交集，放 A 之后 |
| **B7** | 替换「近黑」（表 H）与「阴影/alpha」（表 I） | 独立处理 |
| **B8** | 表 J 内联 SVG 变量、§11 手工项 | 需人工介入 |

> **禁止**用「全部替换 `#1b1` 开头」这类前缀模糊替换——深棕与青绿面板（`#1b211d`）、深绿（`#1b211d`）共用前缀。
